## How to use this file

### Rules for agents

1. **Claim exactly one task.** Set `status: in-progress` and put your agent name in `owner` *before* writing any code.
2. **Never start a task whose dependencies are not `done`.** Check the `deps` column.
3. **Respect the file-ownership map** (§ Ownership). If your task needs a file owned by another in-flight task, mark yourself `blocked` and say so in Notes — do not edit it.
4. **On completion:** report back to the orchestrator with status, each acceptance criterion marked ✅/❌ with evidence, files changed, and anything contradicting ARCHITECTURE.md.
   **Agents in a parallel wave do NOT edit this file** — concurrent writes collide. The orchestrator consolidates all four reports and updates the table once the wave lands. A solo agent working outside a wave may update its own row directly.
5. **Architecture changes go in ARCHITECTURE.md**, not here. If you discover something that invalidates a decision, mark the task `blocked`, write the finding in Notes, and stop.
6. **No task is `done` until its acceptance criteria are verifiably met.** "It compiles" is not acceptance.

### Status values

`todo` · `in-progress` · `blocked` · `review` · `done`

### Ownership map

Prevents two agents editing the same files in one wave.

| Area | Path | Sole owner while in flight |
|---|---|---|
| Infra | `engine/infra/`, `docker-compose*.yml` | infra task of the wave |
| Migrations | `engine/packages/db/migrations/` | **schema task only** — one at a time, always |
| Platform schema | `engine/packages/platform-db/` | schema task |
| API routes | `engine/apps/api/app/api/` | one task per route group |
| Domain logic | `engine/apps/api/app/domain/<module>/` | one task per module |
| Workers | `engine/apps/api/app/workers/` | one task per job file |
| Payload config | `engine/packages/cms/` | CMS task |
| Site config | `jakarta/`, `bali/` | config task |

> **Alembic is single-threaded.** Only one task per wave may create a migration. If your task needs schema, it depends on that wave's schema task.

### Finding 1 — `<br>` word-merge (owner: content-clean → E1.2b)

A bare `<br>` inside a `<figcaption>` is removed without inserting a word boundary:
`"...during the<br>colonial period."` → `"...during thecolonial period."`
28 of 280 figcaption `<br>`s are affected. **It does not change the character count**, so the
char-based loss metric cannot see it — which is why "0.000% loss" and "corrupted captions" are
both true at once. On a magazine, captions carry photographer and museum credits.

**Lesson:** a metric validated by the same code it measures has a blind spot shaped like itself.

> **Correction (QA.2).** This entry previously claimed E1.2b "adds a word-multiset check."

### C4 — identifier typing vs. beacon reality ✅ **RESOLVED (E0.7, migration 0003)**

> Shipped: `entity_id` now nullable, **`target_url text NULL`** added, `stable_uuid` **deleted**

Original problem, for the record:

**My frozen contract was wrong.** `engine.interactions` types `anon_id`, `session_id`, `user_id`,
`entity_id` as `uuid NOT NULL`. The beacon emits none of these as UUIDs — `anon_id`/`session_id`
are 24-char base36 strings, `user_id` is an arbitrary app string, and `entity_id` carries a raw
href for `outbound` and free text for `search`.

E0.5 shipped a deterministic `uuid5` derivation (`stable_uuid`) so real writes succeed. That
unblocked the beacon and is safe for joins — but it is load-bearing scaffolding over a design
error, and it **destroys the outbound URL**: hashing an href to a UUID means we cannot recover
which link was clicked. Partner click attribution and the `ad_events` ledger (E4) depend on
exactly that.

**Resolution — migration 0003 + a beacon update:**

| Column | Change |
|---|---|
| `anon_id`, `session_id` | keep `uuid`; **beacon emits `crypto.randomUUID()`** — they are opaque random ids anyway |
| `user_id` | keep `uuid NULL` — references a real `identities` row |
| `entity_id` | `uuid NULL` — set only for real entities (article/place/event) |
| **`target_url text NULL`** | **new** — the actual outbound href. Required for partner click attribution. |
| `query text NULL` | already added in 0002 |

Once done, `stable_uuid` is deleted rather than depended on.
