# now-eval

E2.7 — evaluation harness + CI gate (`ARCHITECTURE.md` §17). Answers "is
it better?" for every ranking/classification change from here on.

## Scope

Consumes `jakarta/content/extracted/articles.jsonl` (E1.1 contract) and
`jakarta/site/taxonomy-mapping.json` (E1.4) as read-only ground truth.
Does not touch `loader`, `geocode`, `beacon`, `qa-verification`, `cms`,
`db`, or `apps/api`. The systems this package measures (E2.1 classifier,
E3.1 search, E3.5-3.7 rails) do not exist yet — everything here runs
against a pluggable `SystemUnderTest` interface (`src/now_eval/sut.py`)
with two trivial baselines (seeded-random, most-popular) proving the
metrics discriminate real signal from noise.

## Install / run

```bash
cd engine/packages/eval
uv venv && uv pip install -e ".[dev]"
.venv/Scripts/python -m pytest tests/ -q          # 99 tests

# Regenerate every labelled set from source (deterministic, idempotent)
.venv/Scripts/now-eval build-datasets

# Run a trivial baseline and print the §17 report
.venv/Scripts/now-eval run --sut trivial-random

# Record it as the dated baseline CI regresses against
.venv/Scripts/now-eval run --sut trivial-random --record-baseline data/baseline.json --label "..."

# The CI entrypoint: fail on regression vs. the recorded baseline
.venv/Scripts/now-eval check --sut trivial-random --baseline data/baseline.json --gates no-regression
```

Run from the repo root (or anywhere under it) — paths default via
`sources.find_repo_root()`, which walks up looking for
`ARCHITECTURE.md`; override with `--articles`/`--taxonomy` for a
different checkout layout, or to run against `tests/fixtures/*` for a
fast, hermetic sanity check.

## Package layout

```
src/now_eval/
  metrics/
    ndcg.py            DCG@k / nDCG@k -- see the module docstring: this
                        is the single highest-consequence file in the
                        package (a wrong nDCG silently invalidates every
                        future search comparison). Exponential-gain
                        formulation, matching sklearn/trec_eval.
    precision.py        precision@k / recall@k / AP@k (related articles)
    classification.py   accuracy (type) + micro precision/recall (facets)
    itinerary.py         constraint-satisfaction spec/checker for E5
  datasets/
    split.py             deterministic eval/train hold-out (hash of wp_id)
    sources.py            articles.jsonl / taxonomy-mapping.json loaders
    related_articles.py   precision@6 labelled set (primary-category proxy)
    search_queries.py     provisional query set + GSC-export importer
    facet_labels.py        held-out Yoast focus-keyword labels
    type_labels.py          HIGH-confidence category-prior type sample
  sut.py                 SystemUnderTest protocol + trivial baselines
  harness.py              runs a SUT against every labelled set -> metrics
  baseline.py              dated baseline record + the CI regression gate
  cli.py                   `now-eval build-datasets|run|check`
data/
  *.jsonl, baseline.json  version-controlled, regenerated by build-datasets
  PROVENANCE.md            full derivation methodology + known limitations
```

## Metrics -- correctness first

`tests/test_ndcg.py`, `test_precision.py`, `test_classification.py`,
`test_itinerary.py` are hand-computed cases (worked by an independent
bare-formula re-implementation inside the test file itself, or by exact
fraction arithmetic in comments) -- not just re-testing the
implementation against itself. See `PROVENANCE.md` for real numbers on
real data plus how each labelled set was derived.

## Gates (`ARCHITECTURE.md` §17)

| Surface | Metric | Gate | Enforced by |
|---|---|---|---|
| Related articles | precision@6 | no regression | `baseline.Gate("related_articles", ..., "no_regression")` |
| Search | nDCG@10 | no regression | `baseline.Gate("search", ..., "no_regression")` |
| Facet tagging | precision **and** recall | >=0.85 before auto-apply | `baseline.Gate("facet_tagging", ..., "min_threshold", 0.85)` (both metrics) |
| Type classification | accuracy | >=0.95, gates competitor exclusion | `baseline.Gate("type_classification", ..., "min_threshold", 0.95)` |
| Itinerary | constraint satisfaction | 100%, hard fail | `metrics.itinerary.BatchResult.all_satisfied` |

`now-eval check --gates all` enforces every gate above -- this is what
E2.1/E2.2 run once a real classifier/tagger is wired in via
`SystemUnderTest`. `now-eval check --gates no-regression` (what this
package's own CI runs against the trivial baseline) enforces only the
no-regression gates, because a trivial baseline is *expected* to fail
the hard minimums -- that failure is the metric working, not a defect.
See `.github/workflows/engine-eval.yml` and `baseline.check_gates`'s
docstring.

## Hold-out (E2.1 cannot train on these labels)

`datasets/split.py` partitions every `wp_id` into `eval`/`train` via a
salted hash (default 20% eval). `facet_labels.py` and `type_labels.py`
draw exclusively from `eval`; `type_labels.build_type_labels(...,
split="train")` exists only so the trivial most-popular baseline can be
fit without peeking at eval labels. See `tests/test_split.py` and
`PROVENANCE.md` §1.
